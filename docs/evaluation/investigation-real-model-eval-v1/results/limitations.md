# Limits and interpretation

- This study uses ten selected synthetic scenarios, one provider and the effective model ID `deepseek-flash`. It does not estimate production success rates, establish a model ranking or measure live social-platform collection/login behavior.
- Fixture truth, task catalog and rubric were frozen before real task answers. Content SHA256: `c63ed42883d16e73ec0594b9c023fd65a34c90fa10a48f952d887bf2f21d590d`. No expected facts or acceptance rules were changed after viewing outputs.
- Fresh configuration was explicitly provisioned by the user. Production `model_for()` routes fast/reasoning/report to FAST_MODEL; this policy was retained. The response model ID matched the configured ID. An ID returned by an OpenAI-compatible intermediary cannot independently establish the upstream model implementation or version.
- No verified price/version was available for this provider. Monetary cost and currency remain null / NOT_MEASURABLE. Returned SDK token usage is preserved; failed/cancelled calls may have unknown usage. A sum of known calls is only a measured lower bound when any call is unknown. Tokens in failed requests cannot be assumed to be zero or free.
- SDK retries are internal to the production gateway. The recorded request count counts observed SDK create calls, not every possible HTTP retry. A cancelled in-flight call may be absent from the observer's completed measurements; request and token counts are not a billing reconciliation.
- The production search adapter in the isolated harness points to an unavailable embedding worker (`localhost:1`). Real models can choose this tool or dispatch an expert that chooses it. Such failures are retained and attributed to environment/tool execution where supported, without claiming they measure an embedding-enabled deployment or isolating a single cause of later timeout.
- E6's baseline known-ID/source map does not cover every persisted object type. Review items, comments and signals can be returned by real tools but classified as invalid IDs. Original automatic failures are retained. Provisional manual review distinguishes this mapping gap from invented sources; independent review must resolve any acceptance disagreement using the frozen rule, not silently rewrite the baseline.
- E13's numeric detector can flag “0 records” in negated/conditional explanations, and its unavailability detector can miss an English explanation. Fault exposure is checked against actual injected-error/read observations and manual evidence as well; the original automatic outcomes are not rewritten.
- E9 step/tool budgets are recorded thresholds in this runner, not strict request/tool dispatch caps. Exceedances can coexist with deterministic pass. Execution remains bounded by per-task wall-clock deadlines, CLI process deadlines and the selected finite task list. This limitation is reported rather than represented as strict enforcement of the suggested tool count.
- Tool failure counts chiefly recognize failed invocations; a successful invocation with `result.ok=false` (for example `collection_run_unavailable`) can be omitted. The curated observations and manual notes preserve these business-level failures.
- E5 does not count artifact growth as an unexpected mutation. For example repeat-02/IR09's derived propagation artifact increases case artifacts1→2 despite an E5 pass. Artifact behavior and the intended read-only boundary require explicit review; do not infer absence of all writes from E5 alone.
- Positive float `duration_ms` values exist on individual model requests, but the baseline aggregation accepts integers and marks their sum NOT_MEASURABLE. The report exposes individual values; no patch or new fabricated aggregate replaces original raw records. Wall-clock task duration remains measured. Parallel tools/experts prevent simply subtracting summed times to infer orchestration overhead.
- Persisted parent/child tool arrays reflect recorded completion order, with concurrent calls possible. They do not prove a total dispatch ordering. Unproductive-repeat counts require the recorder's exact tool/normalized-argument match and do not establish semantic productivity or absence of all redundant work.
- Isolated file-backed SQLite databases use memory journaling and synchronous=OFF to avoid Windows DDL stalls. Fixtures are synthetic and retained; these settings are never applied to the live application DB. Crash durability and live PostgreSQL behavior are outside the study.
- Known source IDs alone do not prove factual support. Codex provisional six-dimension review is kept separate from deterministic outcomes and from independent ChatGPT GitHub audit, which remains pending. Final acceptance/merge is the user's decision.
- Published files contain selected synthetic excerpts and answers. Source IDs present in the frozen mapping, including unique short prefixes, are replaced by logical keys; unmapped synthetic review/comment/signal IDs are intentionally retained as evidence of mapping failures. Long nested expert instructions are abbreviated. Complete raw reports, request measurements, private configuration receipts and task databases remain local/ignored. Digests identify local artifacts; they are not downloadable GitHub artifacts. Truncated excerpts are labelled.
- No candidate production fix is compared with this baseline. Cross-attempt differences describe observed variability, not causal effects of a code change.
